# LogViewer 性能优化检查清单

## 第一阶段：核心性能优化

### 并行解析
- [x] `parse_log` 函数调用 `parse_lines_parallel` 而非单线程循环
- [x] 多核 CPU 在解析时利用率 > 80%
- [x] 1GB 文件解析时间 < 15s

### 零拷贝实现
- [x] `MmapLine` 结构体使用 `&'a [u8]` 而非 `Vec<u8>`
- [x] `MmapReader::next_line()` 无 `to_vec()` 调用
- [x] 1GB 文件内存占用 < 700MB

### 数据库查询优化
- [x] 键格式使用 16 位十六进制：`log:{file_id}:{entry_id:016x}`
- [x] `get_entries` 使用范围查询直接定位
- [x] 跳转到第 100 万条日志响应时间 < 50ms

### 全文搜索索引
- [x] 倒排索引结构正确：`word:{file_id}:{word_hash} → RoaringBitmap`
- [x] 分词器正确处理中英文
- [x] 搜索覆盖所有日志记录（无 10000 条限制）
- [x] 百万级日志搜索响应时间 < 100ms

## 第二阶段：功能增强

### 时间戳索引
- [x] 时间戳索引键格式正确：`time_idx:{file_id}:{timestamp} → RoaringBitmap`
- [x] 时间范围过滤使用索引而非全表扫描
- [x] 时间过滤响应时间 < 50ms

### 分页加载
- [x] 前端使用 `loadedPages` Map 缓存页面
- [x] 滚动时动态加载可见区域
- [x] 内存中只保留当前需要的页面
- [x] 实现 LRU 页面淘汰策略

### 后端过滤
- [x] `filter_logs` 命令支持组合过滤（级别+时间+搜索）
- [x] 使用 RoaringBitmap 实现位图运算
- [x] 前端调用后端过滤接口
- [x] 级别过滤响应时间 < 10ms

## 第三阶段：健壮性增强

### 文件大小检查
- [x] `MAX_FILE_SIZE` 常量定义为 10GB
- [x] `open_file` 命令检查文件大小
- [x] 超大文件返回友好错误提示
- [x] 不加载超过限制的文件

### 性能测试
- [x] Rust 后端编译通过
- [x] 前端类型检查通过
- [x] 单元测试全部通过（14 个测试）
