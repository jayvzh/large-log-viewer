# LogViewer 日志查看器开发规格

## Why
开发一个高性能的日志文件分析工具，专门用于处理大型日志文件（几百MB至几GB），提供快速分类、搜索和查看功能，提高开发人员和运维人员的日志分析效率。

## What Changes
- 创建基于 Rust + Tauri + Svelte 的高性能 Windows 桌面应用
- 使用 sled 嵌入式数据库实现日志索引和快速查询
- 使用 Rust 内存池技术优化大文件处理
- 使用布隆过滤器 + 位图索引加速查询
- 实现日志分类过滤、搜索、时间筛选功能
- 实现多格式内容查看器（文本、HTML、JSON、XML）
- 采用虚拟滚动技术处理大量日志条目

## Impact
- 新建项目，无现有代码影响
- 目标平台：Windows 10/11

## ADDED Requirements

### Requirement: 技术栈选择
系统 SHALL 采用以下技术栈：

**后端（Rust）**：
- **桌面框架**: Tauri 2.x
- **日志解析**: Rust 原生实现，多线程并行解析
- **文件管理**: 内存映射文件（mmap）
- **索引存储**: sled 嵌入式数据库
- **内存管理**: 内存池（typed-arena / bumpalo）+ LRU 缓存
- **查询引擎**: 布隆过滤器 + 位图索引
- **并发处理**: tokio 异步运行时 + rayon 并行库
- **序列化**: serde + serde_json

**前端（TypeScript）**：
- **前端框架**: Svelte 5 + TypeScript
- **UI组件库**: skeleton 或 自定义组件
- **状态管理**: Svelte Stores（内置）
- **虚拟列表**: svelte-virtual-list 或 自定义实现
- **构建工具**: Vite

**选择理由**：
1. **Tauri**: 打包体积小（<10MB），内存占用低，使用系统 WebView
2. **Svelte**: 编译时优化，无虚拟 DOM，打包体积最小，运行时性能最佳
3. **Rust 后端**: 无 GC 停顿，零成本抽象，适合大文件处理
4. **sled 数据库**: B+树索引，支持快速随机访问、范围查询、持久化存储
5. **内存映射文件**: 零拷贝读取，操作系统自动管理缓存
6. **布隆过滤器**: 快速判断元素是否存在，减少不必要的磁盘/内存访问
7. **位图索引**: 紧凑存储，支持快速位运算（AND/OR/NOT）
8. **内存池**: 减少内存分配次数，避免内存碎片


### Requirement: 文件加载模块
系统 SHALL 提供：
- 支持拖拽加载日志文件
- 支持文件对话框选择
- 支持加载多种格式日志文件（.log, .txt等）
- 使用内存映射文件（mmap）零拷贝读取
- 多线程并行解析（rayon）
- 加载进度实时推送（Tauri Events）
- 支持取消加载操作
- 解析完成后持久化索引到 sled

### Requirement: 日志解析模块
系统 SHALL 提供：
- Rust 高性能解析器，多线程并行解析
- 自动识别常见日志格式
- 按行解析并提取时间戳、级别、记录者、摘要信息
- 支持多行日志合并显示
- 解析结果存储到 sled 数据库

**数据结构设计**：
```rust
struct LogEntry {
    id: u64,              // sled 自增 ID
    file_id: u64,         // 文件标识
    line_number: u64,     // 原始行号
    timestamp: i64,       // Unix 时间戳（毫秒）
    level: LogLevel,      // 日志级别
    logger: SmallString,  // 记录者（小字符串优化）
    summary: SmallString, // 摘要（小字符串优化）
    raw_offset: u64,      // 原始文件偏移量
    raw_length: u32,      // 原始内容长度
}

enum LogLevel {
    Fatal = 0,
    Error = 1,
    Warn = 2,
    Info = 3,
    Debug = 4,
    Trace = 5,
    Other = 6,
}
```

**sled 索引设计**：
```rust
// 主存储：log:{file_id}:{entry_id} -> LogEntry
// 时间索引：time_idx:{file_id}:{timestamp}:{entry_id} -> ()
// 级别位图：level_bitmap:{file_id}:{level} -> RoaringBitmap
// 布隆过滤器：bloom:{file_id}:{word_hash} -> ()
```

### Requirement: 查询引擎
系统 SHALL 提供高效的查询能力：

**布隆过滤器**：
- 用于快速判断关键词是否可能存在
- 减少不必要的索引查询
- 支持多个布隆过滤器组合（AND/OR）

**位图索引**：
- 每个日志级别对应一个位图
- 支持快速位运算：AND（交集）、OR（并集）、NOT（差集）
- 使用 RoaringBitmap 压缩存储

**查询流程**：
```
用户输入搜索词
    │
    ▼
布隆过滤器预判（是否可能存在）
    │ 存在
    ▼
位图索引查询（获取匹配的 entry_id 集合）
    │
    ▼
级别位图过滤（AND 运算）
    │
    ▼
时间范围过滤（sled 范围查询）
    │
    ▼
返回结果
```

### Requirement: 分类过滤模块
系统 SHALL 提供：
- 按日志级别分类：所有、致命、错误、警告、信息、调试、跟踪、其它
- 实时统计各分类数量（位图基数统计）
- 单选分类过滤（点击切换）
- 分类标签显示对应数量

**支持的日志级别**：
- FATAL（致命）- 红色 #f44747
- ERROR（错误）- 红色 #f44747
- WARN（警告）- 黄色 #d7ba7d
- INFO（信息）- 蓝色 #569cd6
- DEBUG（调试）- 灰色 #808080
- TRACE（跟踪）- 灰色 #606060
- OTHER（其它）- 默认色 #cccccc

### Requirement: 搜索模块
系统 SHALL 提供：
- 模糊搜索（布隆过滤器预判 + 位图索引）
- 正则表达式搜索（Rust regex 库）
- 按时间范围筛选（sled 范围查询）
- 搜索条件实时生效
- 搜索结果高亮显示

**时间筛选选项**：
- 今天
- 昨天
- 最近7天
- 最近30天
- 自定义范围

### Requirement: 日志查看模块
系统 SHALL 提供：
- 多格式内容查看：文本、浏览器（HTML）、JSON、XML
- 日志详情显示
- 支持内容复制
- 语法高亮
- JSON/XML 格式化显示，支持展开/折叠

### Requirement: 性能指标
系统 SHALL 满足：
- 加载1GB日志文件时间不超过15秒
- 内存占用不超过文件大小的 0.8 倍
- 筛选和搜索操作响应时间小于 100ms
- 支持至少 1000 万条日志记录的流畅滚动
- 快速跳转：从第1条跳转到第100万条 < 50ms
- 打包体积小于 10MB

### Requirement: 快捷键支持
系统 SHALL 支持：
- F5: 刷新日志
- Ctrl+O: 打开文件
- Ctrl+F: 聚焦搜索框
- Escape: 重置筛选条件
- Ctrl+C: 复制选中日志内容

### Requirement: 数据持久化
系统 SHALL 提供：
- 日志索引持久化到 sled 数据库
- 应用重启后无需重新解析已加载的文件
- 支持清理旧索引数据
- 索引文件存储在用户 AppData 目录
